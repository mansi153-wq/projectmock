AI-Powered Mock Test & Online Assessment Platform — Full Project Roadmap
1. What this project does

A web app where an Admin creates exams by picking subject/topic/difficulty, AI (Google Gemini) auto-generates MCQ questions, students take the exam under a server-controlled timer, answers are auto-evaluated, and a live leaderboard + AI feedback is shown afterward.

5. How to get the project running from scratch (for a new teammate)
Backend setup
bash
cd server
npm install

This installs everything already listed in server/package.json, including:

express, cors, dotenv — core server
nodemon (dev dependency) — auto-restarts server on file changes
mysql2 — MySQL connection
bcrypt — password hashing
jsonwebtoken — JWT auth

Create a .env file in server/ (copy .env.example and fill in real values):

env
PORT=5000

DB_HOST=localhost
DB_PORT=3306
DB_USER=root
DB_PASSWORD=your_actual_mysql_password
DB_NAME=mock_test

JWT_SECRET=any_long_random_string

CLIENT_URL=http://localhost:5173

Never commit .env — it's already in .gitignore. Only .env.example (with placeholder values) gets committed.

Run the backend:

bash
npm run dev

Should print: Server running on http://localhost:5000

Frontend setup
bash
cd client
npm install

This installs everything in client/package.json, including:

react, react-dom — core React (from Vite scaffold)
react-router-dom — page routing
axios — API calls

Run the frontend:

bash
npm run dev

Should print a local URL like http://localhost:5173

Database setup (one-time, per machine)

Log into MySQL:

bash
mysql -u root -p

Then run:

sql
CREATE DATABASE mock_test;
USE mock_test;

Then create the tables (see section 7 below for current table definitions).

6. API structure so far

Base URL: http://localhost:5000/api

Method	Endpoint	Auth required	Purpose
GET	/health	No	Check server + DB are alive
POST	/auth/register	No	Create a new user (admin or student)
POST	/auth/login	No	Log in, returns JWT token
POST	/exams	Yes (admin)	Create a new exam
GET	/exams/my-exams	Yes (admin)	List exams created by logged-in admin

How auth works: After login, the frontend stores the JWT token (in localStorage) and automatically attaches it as Authorization: Bearer <token> on every future request (handled by client/src/services/api.js). Backend routes use authenticateToken middleware to verify the token, and requireAdmin/requireStudent to check role.

Testing APIs manually (Thunder Client): For any protected route, go to the Auth tab in Thunder Client, select Bearer, and paste a token obtained from a /auth/login request.

10. Key design decisions (important — don't deviate without discussion)
Correct answers are never sent to the student's browser during an exam. Only the admin preview screen shows them.
Gemini is called once per exam (when the admin clicks "Generate Questions"), not once per student. Everyone taking the exam gets the same question set from the database.
The backend is the authority for exam timing, evaluation, scores, and access control — the frontend only displays things and sends requests. Never trust frontend-only validation for anything security-sensitive.
Exam codes are generated by the backend, not typed by the admin, guaranteeing uniqueness.
Passwords are never stored in plain text — bcrypt hash only.
